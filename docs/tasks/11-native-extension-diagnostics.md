# 11：让原生搜索扩展失败可诊断

**What to build（交付行为）：** fzf原生扩展加载失败时显示具体原因与构建指引，成功时可确认实际启用。

**Blocked by（阻塞依赖）：** 无（可开始）。

**Status：** ready-for-agent（用户已确认拆分与依赖，未开始实施；执行前须满足Blocked by）

**归属：** D；[治理SPEC](../spec.md) R08 / ID06；验收 AC08。

## 验收标准

- [ ] 保留本机当前fzf可加载的正常路径，检查真实extension启用而非只检查目录存在。
- [ ] 在隔离测试中模拟缺构建产物或加载失败，给出错误原因、对应平台工具及显式构建入口。
- [ ] 不在首屏自动下载或编译，失败提示不重复刷屏；后续正常操作可继续并清楚说明状态。
- [ ] Windows原生产物和macOS产物区分验证，不共享DLL；相关SQLite模块检查不冒充数据库读写验收。
- [ ] 同步依赖排障和原生构建文档。

## 范围与交付记录

不宣称当前fzf缺失，不在本任务中升级rocks/rest或替换picker。

完成时追加复现、改动原因、执行环境/revision、实际结果、未验证边界和恢复方式；同步当前设计、教程、问题状态及决策记录。候选评估票以可复现比较和选型材料完成，不因评估结束自动获得迁移状态。
