## 推荐接续方式

1. 本拆分已确认并进入执行；先查各票最新状态与实施证据，避免重复处理已完成工作。
2. A批缺陷已由本轮实现及37/37最终功能回归闭环；新失败先核对revision并沿原证据定位。
3. 原始可执行前沿已由本轮实现消化。编号是拓扑顺序，后续只对仍开放的实际边界接续，不从全部ready重新开始。
4. B/C/D/E已完成Windows实施；20已保存三轮独占性能数据，首屏较源基线更慢、搜索更快，下一轮性能优化据此剖析。
5. 21是指定revision的双平台验收，不为无实机或未授权AI账号场景虚报完成。后续更新按影响范围补验。
6. 22–26是候选评估，结论可以是保留现有方案；选型明确后再创建真正迁移票。不把五项候选一起替换。
7. 每票包含用户行为、集成验证、当前教程和决策回执；不另设“只改代码/只写测试/最后统一补文档”的横向任务。

没有发现必须先进行大范围机械重构才能实现的证据，因此不增加预重构任务。01是实际回归缺陷的闭环，不是抽象基础设施工程。

## 执行与完成状态

任务正文的Status为执行状态唯一来源；本索引不维护另一份逐票勾选副本。Blocked by未完成的票不得因标了ready-for-agent而提前执行。

实施时先核对当前源码与原证据是否漂移，复用有效证据；每票记录测试实际运行在哪个平台。未验macOS、服务缺失或未完成真实云端AI建议分别列出，不能用高亮、模块require或本地初始化代替。

候选票可以在隔离配置试验，但不能覆盖日常数据；需要取舍未获决定时保留待决状态。涉及多个共享配置位置的工作按现有接口修改，不因独立任务强制引入抽象层。
