# 01：查清并修复Go回归超时与进程遗留

**What to build（交付行为）：** 让Go启动回归在成功、失败和超时三条路径均能结束，保留失败证据，且不遗留本次测试创建的进程。

**Blocked by（阻塞依赖）：** 无（可开始）。

**Status：** ready-for-agent（用户已确认拆分与依赖，未开始实施；执行前须满足Blocked by）

**归属：** A；[治理SPEC](../spec.md) G01 / ID01、ID08；验收 AC02、AC09。

## 验收标准

- [ ] 复现30秒超时，记录Neovim及本次Git子进程的创建、退出与输出管道状态，区分应用阻塞和测试等待。
- [ ] 用可区分解释的对照确认Git停滞及句柄继承是否相关，修复已确认的责任路径；不以加长超时或停用Git功能作为结案。
- [ ] 正常退出、失败和超时后均无本次遗留进程；清理只作用于测试创建的进程，不影响用户会话。
- [ ] 保留原停滞Go工具链fixture回归，并验证该禁用服务路径不调用fixture；GoBuild和格式化入口仍存在。
- [ ] PowerShell、Git Bash和zsh记录复现与修复后的退出结果；Go故障记录、问题台账和决策追加新回执。

## 范围与交付记录

只处理G01及其共享进程生命周期；不据遗留Git进程直接认定根因，也不批量更新插件。

完成时追加复现、改动原因、执行环境/revision、实际结果、未验证边界和恢复方式；同步当前设计、教程、问题状态及决策记录。候选评估票以可复现比较和选型材料完成，不因评估结束自动获得迁移状态。
