# Neovim 跨平台配置治理 SPEC

状态：**结论已接受，实施待分批验收**。固化日期：2026-10-22。

用户本轮明确要求总结问题、接受上述结论，并使用 Matt `to-spec` 固化为本地规格。本文定义后续目标与验收契约；[整体设计](design.md)描述当前实现，[教程](tutorial.md)说明当前操作，[决策记录](decisions.md)保留追加历史。目标行为不表示现有配置已经具备。

基线：本地 `main` 的 `f7de791`，Neovim 0.12.6，39个Git插件、14个Coc扩展。此前5批提交已完成，未推送。完整证据与本地测试记录见文末，不把历史通过结果覆盖为最新通过。

## Problem Statement（问题与已核实结论）

用户需要从 Windows PowerShell、Git Bash、zsh 和 macOS 使用一套可移植配置，打开代码及时可用，语言导航正确，大文件不卡死，插件维护可控，并能用主题辨认项目。

当前主要问题如下；R编号沿用综合评审，G01为分批提交前新增的回归失败。

| 编号 | 当前事实 | 影响与结论 |
|---|---|---|
| R01 | Go局部`gd`等键指向vim-go；默认定义服务为gopls，但gopls已关闭，Coc清单也没有Go专用服务 | 默认跳转链不通，必须联合修正服务与映射 |
| R02 | 终端Esc发送exit；普通代码中`]c`重置整个buffer未暂存修改；空格gd仅有描述 | 容易退出任务或丢失改动，键位、帮助和实际动作需统一 |
| R03 | 短JS buffer编辑成30000字节单行，仍未触发大文件保护 | 读取保护已存在，编辑增长的长行检查有缺口 |
| R04 | 全文搜索绕过gitignore；目录在Lua结果层过滤；正斜杠lib路径误伤合法源码，反斜杠不命中 | 扫描范围、结果正确性和跨平台策略需一起修复 |
| R05 | Go/Python/Vue专用服务未列入Coc清单；Lua调用本机不存在的lua-lsp且关闭补全 | 高亮通过不能作为完整语言能力通过的证据 |
| R06 | lualine要求globalstatus，最终laststatus=2；主题仅在启动按cwd子串分三类 | 状态栏契约冲突；尚无自动项目主题 |
| R07 | 空启动触发UIEnter约1秒后，39项中29项加载；空buffer也能触发NormalFile | 存在收敛启动工作量的空间，需要测量，不能只追求首屏数字 |
| R08 | 本机fzf扩展可加载，但配置静默处理加载失败；兼容模块依赖特定上游行为 | 更新和跨机器部署需要可见诊断及回归 |

| M01 | legendary.nvim和vim-tutor-mode已归档 | 接受优先迁移的方向，保留自定义命令、进度和频率行为 |

已完成的高亮、blame、Windows rest.nvim、Copilot本地接入、共享Coc目录、显式部署和宿主升级继续保留。macOS实机、授权后的真实AI建议、完整语言服务及候选插件性能仍有验收缺口。

## Solution（接受的方向）

1. **先恢复正确行为，再优化和更新。** 处理Go导航、危险键位、长行增长、语言服务、状态栏及G01，再修搜索共享路径。
2. **近期保留Coc和现有主要工作流。** 补齐服务并明确职责；vim-go保留构建、测试和格式化，避免重复语言服务。原生LSP加blink属于独立候选迁移。
3. **插件分批维护。** 先迁移两个归档组件，再按兼容性更新维护中的组件；Treesitter、语言服务和Go工作流的大迁移分别验收。
4. **主题按活跃项目识别。** 复用已有主题与项目根识别，不新增主题管理依赖。默认推荐一项目一进程；同进程切换项目时更新全局主题。
5. **源码跨平台共享，运行产物按平台部署。** 编辑启动不隐式联网安装、编译或等待工具链下载；保留TLS校验和用户数据。
6. **规范、现状与证据各司其职。** 本SPEC保存已接受的要求，当前实现与教程随实施同步；两仓库继续记录，Vault提供入口而不复制完整契约。

候选插件的具体选型、每个真实项目的主题分配和未量化的性能目标仍需对应证据；接受上述方向不等于已经选定所有候选或完成迁移。

## User Stories（用户故事）

1. 作为Windows用户，我希望从PowerShell、Git Bash或zsh进入同一配置和扩展状态，避免同机行为分裂。
2. 作为macOS用户，我希望复用相同源码、按键和工作流，在本机构建原生产物后使用。
3. 作为开发者，我希望普通编辑启动无需等待下载、编译器检测或项目工具链安装，及时看到首屏。
4. 作为Go开发者，我希望定义、引用、重命名、悬浮文档和跨包跳转由可工作的同一语言服务负责。
5. 作为Go开发者，我希望继续明确执行构建、测试和格式化，并在失败时得到有用的结果。
6. 作为Python开发者，我希望语言服务使用正确解释器，提供导航、补全和诊断。
7. 作为前端开发者，我希望JS、TS、React、Vue2和Vue3分别有适配的高亮与语言服务。
8. 作为Lua配置维护者，我希望服务命令存在，补全开关与预期一致。
9. 作为终端用户，我希望按Esc只离开终端输入模式，保留shell和前台任务。
10. 作为Git用户，我希望用导航键切换差异，用明确的操作暂存或重置，避免误删改动。
11. 作为代码阅读者，我希望Git blame在普通受跟踪文件中可用，并在大文件中服从性能保护。
12. 作为大文件用户，我希望字节数、行数和长行阈值在首次打开及编辑增长时都能保护编辑器。
13. 作为多文件用户，我希望大文件保护只影响相关buffer，切回普通文件后功能正常。
14. 作为搜索用户，我希望默认搜索尊重gitignore，且能明确选择搜索忽略文件。
15. 作为搜索用户，我希望合法的源码lib目录可以找到，目录规则在两平台结果一致。
16. 作为中文搜索用户，我希望常规Unicode搜索不额外依赖PCRE2构建能力。
17. 作为插件使用者，我希望原生扩展失败时有清楚诊断，能够定位缺少的工具或构建产物。
18. 作为维护者，我希望归档插件迁移保留原有命令、教程进度和已使用的频率排序行为。
19. 作为维护者，我希望每次更新范围明确，能按锁定版本及对应平台产物恢复。
20. 作为多项目开发者，我希望主题跟随活跃项目，终端、帮助和文件树不把主题误切走。
21. 作为多窗口用户，我希望状态栏选项一致，切换同主题项目时不重复初始化。
22. 作为日常用户，我希望用buffer管理文件、window对照代码、tab保存布局，并在教程查到实际按键。
23. 作为HTTP用户，我希望Windows和macOS使用相同rest请求入口，并保持TLS验证。
24. 作为AI用户，我希望继续使用已选官方Copilot Free，由自己完成账号授权，大文件自动停用昂贵分析。
25. 作为后续维护者，我希望从规格、设计、故障证据和追加决策追溯状态，不把历史结果误当当前通过。
26. 作为测试执行者，我希望失败和超时后能定位及结束测试自己的进程，避免测试挂住或影响用户会话。

## Implementation Decisions（实现决策）

本节描述模块职责与契约，不固定文件位置或代码实现。

### ID01：部署、启动与平台边界

保留启动引导、平台工具发现和显式部署三个职责。Windows的shell路径在系统边界转换；工具通过argv启动，避免盘符硬编码和命令字符串拼接。源码根与运行数据根独立计算，Coc状态在同机各shell共享。

依赖安装、更新和原生构建只在明确操作时执行；缺失时提示操作入口。编辑首屏不执行同步下载、编译器目标探测或Go工具链安装。正常启动、进程退出与后台任务生命周期均需可观察。

### ID02：语言服务职责

近期由Coc承担语言补全、诊断和导航，Treesitter承担语法结构与高亮。Go的局部映射不得进入被关闭的服务；vim-go保留明确任务命令。补齐Go、Python和Lua的实际服务依赖；Vue按Vue2.6、2.7、3及TypeScript组合核验，选择相符服务版本。

现有14项Coc扩展版本一致不等于服务齐全。原生LSP和blink若后续被选中，必须覆盖Coc已有语言、命令、诊断、格式化、Vista及映射，独立迁移。

### ID03：键位与帮助

终端Esc统一离开输入模式，退出或停止任务保留明确入口。`]c`和`[c`恢复差异/hunk导航语义；暂存及重置使用明确命名的操作入口，重置前给确认。最终具体组合以实施时现有键位占用为依据，同步which-key与教程。

所有帮助条目应有真实动作，清理无动作的描述和冲突前缀；保留现有有效行为。Neorg的LocalLeader、Copilot与surround的前缀等待等在涉及修改时验收，不直接删除插件或吞掉快捷键。

### ID04：逐buffer的大文件保护

沿用现有阈值：总字节大于1MiB、行数大于20000或单行大于20000字节。读取和编辑变化均经过相同判定契约；编辑检查优先覆盖变化行，避免每次按键遍历全文。

达到阈值后停止该buffer的Coc、Copilot、Treesitter、折叠及相关昂贵附加，继续基础阅读编辑。明确验证首次大文件、先普通后大文件及多buffer切换。缩小或撤销后恢复功能的方式必须可解释并验证，至少允许保存后重开正确恢复，不承诺未经验证的自动重建。

### ID05：搜索正确性先于替换搜索器

普通搜索尊重gitignore；搜索忽略文件为显式入口。扫描排除由ripgrep的跨平台glob承担，Telescope结果层过滤不承担减少扫描量的职责。不把所有lib、build名称等同于构建产物；保留合法源码。

默认使用支持Unicode的常规正则引擎，高级PCRE2按需选择。节流参数根据首次结果与输入延迟测量决定。先修同一搜索策略，再比较Telescope、fzf-lua和Snacks，不能以架构描述代替实测。

### ID06：插件维护与诊断

归档legendary优先评估已有Telescope及which-key接替，tutor优先评估内置Tutor；迁移前核对自定义命令、进度、语言和频率行为，清理依赖前确认没有其他使用者。原生注释可评估，但需保留Vue/JSX嵌套语言注释。

维护中的插件按功能分批选择明确提交，记录锁版本及原生构建变化。fzf实际加载成功的现状继续保留；加载失败须给诊断。go/rest适配模块随上游更新重新核对，不能无条件永久叠加。

### ID07：主题、状态栏和懒加载

主题解析以活跃普通文件的项目根为依据，支持Git worktree，没有Git时按明确workspace/package标记回退，空首页使用cwd。不得在每次进入buffer时同步运行Git。规则兼容路径分隔符和各平台大小写语义，项目重名和monorepo匹配要有明确优先级。

在普通文件进入和工作目录改变时更新；终端、帮助、quickfix、文件树等保留上一个活跃项目主题。仅目标主题变化时应用，避免重复初始化。完整colorscheme为进程级，默认不设计两个tab同时保持独立完整主题。真实项目的配色表待配置，不擅自替用户指定。

状态栏的globalstatus和最终laststatus统一为同一模式，具体全局或逐窗口模式在实施时按当前使用场景明确。搜索、命令面板及Neorg传递依赖按需加载，避免空首页触发无关代码工作，同时维持必要功能就绪时间。

### ID08：证据与文档

本SPEC保存已接受方向，综合评审保留日期快照，当前设计和教程随真实实现更新。每批追加决策与验收回执，不改写历史通过或失败。Vault只保存规格入口、跨仓库回执和接续说明。

G01先调查Git子进程、退出路径和Windows管道句柄，确认原因后修责任模块及测试退出路径；保留旧Go工具链阻塞回归，二者分别验证。

## Testing Decisions（验收决策）

优先使用现有的**配置后Neovim子进程加临时项目**这一集成测试边界，从外部验证可见动作、退出结果和子进程行为。复用已有高亮/blame、大文件、Go、UI、Coc、AI及本地HTTP回归；只有项目主题和搜索范围等新行为需要新增对应场景，不为每个内部函数增加测试层。

测试项目、Git记录和本地HTTP服务隔离创建；故障注入只进入测试子进程环境。超时清理限于测试自己创建的进程树，保留失败信息，不结束用户编辑器或其他任务进程。

下表为接受的验收入口；实施回执需分别记录，不将规格中的要求写成已完成结果。

## Out of Scope（本轮边界）

- 本轮只固化规格和接受记录，不执行功能修复、插件更新、依赖安装或新的宿主升级。
- 不全量更新插件，不预先认定native LSP、blink、go.nvim、fzf-lua或Snacks性能胜出。
- 不为每个tab构建完整独立主题，不增加项目管理插件，不删除既有Neorg工作流。
- 不关闭TLS验证、不依赖诊断临时目录、不复制跨平台DLL、不覆盖用户数据或重写Git历史。
- 不处理用户AI账号授权，不发布外部工单或推送远端；免费服务配额以使用时官方政策为准。
